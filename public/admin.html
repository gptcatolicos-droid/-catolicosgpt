🛡️ Migrar imágenes locales a Cloudinary

⚠️ Acción crítica para no perder infografías: Las imágenes guardadas localmente en /public/infografias/*.jpg son frágiles — un deploy puede borrarlas. Este botón las sube TODAS a Cloudinary (preservando el slug, así las URLs públicas como catolicosgpt.com/infografias/corpus-christi NO cambian — el SEO en Search Console queda intacto).

📘 ¿Qué hace exactamente este botón?
  1. Recorre el catálogo de infografías
  2. Detecta las imágenes con URLs locales (/infografias/...)
  3. Las sube a Cloudinary con context-metadata (slug, título, descripción)
  4. Actualiza el catálogo con la nueva URL de Cloudinary
  5. Backup: guarda la URL local original en urlOriginalLocal

SEO: Las URLs públicas catolicosgpt.com/infografias/{slug} NO cambian (el slug es lo único que importa para Search Console). Solo cambia la URL interna de la imagen.

💾 Persistencia & Recovery

Render.com tiene filesystem efímero: cada deploy borra el catálogo local. Cloudinary preserva las imágenes y su metadata. Usa este botón después de cada deploy para reconstruir el catálogo.

📘 Cómo persistir entre deploys (Render Disk)

Opción A (recomendada): En Render.com → tu service → Disks → Add Disk:

  • Name: catolicosgpt-data
  • Mount path: /data
  • Size: 1 GB (~$0.25/mes)

Luego agrega una env var:

DATA_DIR=/data

Opción B (gratis): Cada deploy: ejecuta este rebuild → recupera todo desde Cloudinary.
